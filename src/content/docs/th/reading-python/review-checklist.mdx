นี่คือ checklist ที่ควรไล่ดู — ด้วยตา บน diff ไหนก็ได้ ของคุณเองหรือของ AI — หลังจากเครื่องมือใน **[Verification Tools](/python/th/reading-python/verification-tools/)** รันแล้วสะอาด มันจงใจทำให้อยู่ในหนึ่งหน้ากระดาษพิมพ์: checklist ที่ไม่มีใครเปิดดูจริงตอนรีวิวไม่มีค่าอะไรเลย ทุกบรรทัดลิงก์ไปบทที่อธิบายว่า *ทำไม* และลิงก์ไปหมายเลข pattern ที่ตรงกันใน **[AI Bug Catalog](/python/th/reading-python/ai-bug-catalog/)** ที่มันช่วยป้องกัน

## Mutability

- default argument ใช้ mutable literal (`= []`, `= {}`, `= set()`) แทนที่จะเป็น `= None` หรือเปล่า? Catalog #1 ดู **[Functions](/python/th/basics/functions/)**
- `lambda` หรือ nested function ใน loop close over ตัวแปร loop เอง แทนที่จะเป็นค่าของมันในแต่ละรอบหรือเปล่า? Catalog #2 ดู **[Closures](/python/th/functions-deep/closures/)**
- function ที่ดูเหมือน read-only จริง ๆ mutate argument ที่เป็น `list`/`dict` ในที่เดิม (`.sort()`, `.append()`, `x[i] = ...`) โดยไม่บอกไว้เลยหรือเปล่า? Catalog #3 ดู **[Lists & Tuples](/python/th/data-structures/lists-tuples/)**
- `[[...] * n] * m` (หรือ container ของ container ที่ทำซ้ำด้วย `*`) สร้าง inner object ที่แชร์กันตัวเดียว แทนที่จะเป็นตัวอิสระต่อกันหรือเปล่า? Catalog #4 ดู **[Lists & Tuples](/python/th/data-structures/lists-tuples/)**
- class attribute ที่ประกาศระดับ class (ไม่ใช่ใน `__init__`) เป็น mutable object ที่ถูกแชร์ทุก instance หรือเปล่า? Catalog #15 ดู **[Classes](/python/th/oop-data-model/classes/)**

## Errors

- มีการใช้ `is` ในจุดที่ควรเป็น `==` — เทียบค่าแทนที่จะเช็ค singleton (`None`/`True`/`False`) หรือเปล่า? Catalog #5 ดู **[Variables & Types](/python/th/basics/variables-types/)**
- มี bare `except:`, `except Exception: pass` หรือ (ใน async code) `except BaseException` คั่นอยู่ระหว่าง `await` กับ `.cancel()` ของ task หรือเปล่า? Catalog #6 ดู **[Exceptions](/python/th/typing-errors/exceptions/)**
- มี `raise e` อยู่ใน `except ... as e:` ที่ตั้งใจใช้ bare `raise` หรือเปล่า? Catalog #7 ดู **[Exceptions](/python/th/typing-errors/exceptions/)**
- `assert` validate external input (argument, user input, API response) แทนที่จะเป็น internal invariant หรือเปล่า? มันหายไปภายใต้ `-O` Catalog #8 ดู **[Exceptions](/python/th/typing-errors/exceptions/)**

## Async & concurrency

- ทุก call ที่คืน coroutine ถูก `await` จริงหรือถูกส่งให้ `asyncio.create_task`/`asyncio.gather` หรือเปล่า? Catalog #9 ดู **[asyncio basics](/python/th/async-concurrency/asyncio-basics/)**
- ผลลัพธ์ของ `asyncio.create_task(...)` ทุกตัวถูกเก็บไว้ที่ไหนสักแห่งที่มี lifetime ยาวกว่า function ที่สร้างมันหรือเปล่า? Catalog #10 ดู **[Tasks & gather](/python/th/async-concurrency/async-await/)**
- มี `async def` function ตัวไหนเรียก blocking function (`time.sleep`, synchronous HTTP client, blocking file I/O) แทนที่จะเป็นเวอร์ชัน `await`-based ของมันหรือเปล่า? Catalog #11 ดู **[GIL & threads](/python/th/async-concurrency/gil-threads/)**
- shared mutable state ถูกอ่านแล้วเขียนคาบเกี่ยว `await` โดยไม่มี `asyncio.Lock` หรือเปล่า? Catalog #12 ดู **[Tasks & gather](/python/th/async-concurrency/async-await/)**
- ทุกการเรียก `multiprocessing.Pool`/`Process` อยู่หลัง `if __name__ == "__main__":` หรือเปล่า? Catalog #13 ดู **[multiprocessing](/python/th/async-concurrency/multiprocessing/)**

## Typing

- class นิยาม `__eq__` โดยไม่นิยาม `__hash__` ด้วย (หรือยอมรับโดยตั้งใจว่า instance จะ unhashable) หรือเปล่า? Catalog #14 ดู **[Dunder methods](/python/th/oop-data-model/dunder-methods/)**
- มีการใช้ `Any` ในจุดที่มี type จริงให้ใช้ได้ หรือมี `# type: ignore` ที่ไม่มี error code เฉพาะเจาะจงหรือเปล่า? Catalog #16 ดู **[Type hints](/python/th/typing-errors/type-hints/)**
- parameter หรือ return value ที่เป็น `X | None` (หรือ `Optional[X]`) ถูกใช้โดยไม่มีการเช็ค `None` ก่อนหรือเปล่า? Catalog #17 ดู **[Type hints](/python/th/typing-errors/type-hints/)**
- `list[Subtype]` ถูกส่งไปในจุดที่คาดหวัง `list[Supertype]` หรือเปล่า — และ `Sequence`/`Iterable` (covariant) ควรเป็น parameter type ที่ถูกต้องแทน `list` หรือเปล่า? Catalog #18 ดู **[Type hints](/python/th/typing-errors/type-hints/)**

## Resources & security

- โค้ดเรียก `datetime.utcnow()` (deprecated, naive) แทนที่จะเป็น `datetime.now(timezone.utc)` หรือเปล่า? Catalog #19 ดู **[stdlib tour](/python/th/stdlib-testing-tooling/stdlib-tour/)**
- ทุกการเรียก `open()` อยู่ใน `with` block และส่ง `encoding=` อย่างชัดเจนหรือเปล่า? Catalog #20 ดู **[stdlib tour](/python/th/stdlib-testing-tooling/stdlib-tour/)**
- มีการเรียก `subprocess` ตัวไหนใช้ `shell=True` กับ string ที่สร้างจาก external input หรือเปล่า? Catalog #21 ดู **[stdlib tour](/python/th/stdlib-testing-tooling/stdlib-tour/)**
- ทุก `@patch("...")` target string ตรงกับที่โค้ดที่ถูกทดสอบ import ชื่อนั้นมาจริง ๆ หรือเปล่า — module ที่เรียกใช้ ไม่ใช่ module ที่นิยาม? Catalog #22 ดู **[pytest](/python/th/stdlib-testing-tooling/pytest/)**
- ทุก dependency ถูก pin หรือเปล่า และ `pip-audit`/เครื่องมือ audit ของ `uv` ถูกรันกับ lockfile เมื่อไม่นานมานี้หรือเปล่า? มีการติดตั้งด้วย `sudo pip` ที่ไหนหรือเปล่า? Catalog #23 ดู **[venv, pip & uv](/python/th/stdlib-testing-tooling/venv-pip/)**

## Tooling & style

- โค้ดที่เป็น library เรียก `print()` ในจุดที่ควรเป็น `logging` — อะไรก็ตามที่ผู้เรียกต้อง filter, redirect หรือปิดเสียงได้ — หรือเปล่า? Catalog #24 ดู **[Logging](/python/th/stdlib-testing-tooling/index/)**
