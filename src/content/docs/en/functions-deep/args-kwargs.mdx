## Parameters and arguments

Python distinguishes between **parameters** (names in the function definition) and **arguments** (values passed at call time).
Python gives you fine-grained control over how callers can supply those values.

## Positional and keyword arguments

By default, every parameter can be supplied positionally or by keyword name.

```python
def connect(host: str, port: int, timeout: int = 30) -> str:
    return f"{host}:{port} (timeout={timeout}s)"

# Positional
connect("localhost", 5432)

# Keyword — order does not matter
connect(port=5432, host="localhost")

# Mixed — positional first, then keyword
connect("localhost", port=5432, timeout=60)
```

`timeout` has a **default value** of `30`, making it optional.
Positional arguments must always come before keyword arguments at the call site.

## Variadic positional args: `*args`

Prefix a parameter with `*` to collect any number of positional arguments into a **tuple**.

```python
def total(*amounts: float) -> float:
    return sum(amounts)

print(total(10.0, 20.5, 5.0))  # 35.5
print(total())                  # 0
```

`sum()` on an empty iterable returns the int `0` unless you pass a `start` value, e.g. `sum(amounts, 0.0)`.

## Variadic keyword args: `**kwargs`

Prefix a parameter with `**` to collect any number of keyword arguments into a **dict**.

```python
def log_event(event: str, **metadata) -> None:
    parts = [f"event={event}"]
    for key, value in metadata.items():
        parts.append(f"{key}={value}")
    print(", ".join(parts))

log_event("login", user_id=42, ip="127.0.0.1")
# event=login, user_id=42, ip=127.0.0.1
```

`**kwargs` is a **fresh dict on every call** — it is never shared between calls, even mutating it inside the function has no effect on the next call:

```python
def collect(**kwargs):
    kwargs["seen"] = True
    return kwargs

first = collect(a=1)
second = collect(b=2)
print(first)               # {'a': 1, 'seen': True}
print(second)              # {'b': 2, 'seen': True}
print(first is second)     # False — two different dict objects
```

This is a different rule from the mutable default argument trap covered later in this lesson: a *default value* like `items=[]` is created once at definition time and shared, but `**kwargs` itself is built freshly by Python on every single call, regardless of defaults.

## Keyword-only parameters

Any parameter listed **after a bare `*`** (or after `*args`) can only be supplied by keyword — never positionally.
This makes APIs self-documenting and prevents argument order mistakes.

```python
def send_email(to: str, subject: str, *, cc: str = "", bcc: str = "") -> None:
    print(f"To: {to} | Subject: {subject} | CC: {cc} | BCC: {bcc}")

send_email("alice@example.com", "Hello", cc="bob@example.com")
# Calling send_email("a@b.com", "Hi", "c@d.com") would raise TypeError
```

## Positional-only parameters: `/`

Any parameter listed **before a bare `/`** can only be supplied positionally — never by keyword name. This is the mirror image of keyword-only `*`, and it exists for the same reason: it lets a library author rename an internal parameter later without breaking callers who never depended on that name.

```python
def divide(numerator, denominator, /, *, round_to=2):
    return round(numerator / denominator, round_to)

print(divide(10, 4))              # 2.5 — positional, as required
print(divide(10, 4, round_to=0))  # 2.0 — round_to is keyword-only, after *

divide(numerator=10, denominator=4)
# TypeError: divide() got some positional-only arguments passed as keyword arguments: 'numerator, denominator'
```

Everything before `/` is positional-only, everything after a bare `*` is keyword-only, and anything in between (with no `/` or `*` around it) can be passed either way — exactly the default behavior every parameter had before this lesson introduced `/` and `*`.

## Unpacking at call sites: `*` and `**`

The same `*`/`**` syntax that *collects* arguments inside a function definition also *spreads* a sequence or mapping into separate arguments at a call site:

```python
def connect(host: str, port: int, timeout: int = 30) -> str:
    return f"{host}:{port} (timeout={timeout}s)"

args = ("localhost", 5432)
kwargs = {"timeout": 60}
print(connect(*args, **kwargs))
# localhost:5432 (timeout=60s) — same as connect("localhost", 5432, timeout=60)
```

`*args` in a **definition** means "gather extra positional arguments into a tuple named `args`." `*args` at a **call site** means "unpack this iterable into separate positional arguments." The symbol is the same; whether you are defining or calling tells you which direction it goes.

## The forwarding pattern: `def wrapper(*a, **kw)`

Combining "gather" (in the signature) with "spread" (in the body) lets a wrapper function accept absolutely any call shape and forward it unchanged to another function — this is exactly how every decorator's `wrapper` in the [Decorators lesson](/python/en/functions-deep/decorators/) stays compatible with whatever function it wraps:

```python
def base(a, b, *, c=10):
    return a + b + c

def wrapper(*a, **kw):
    print("forwarding", a, kw)
    return base(*a, **kw)

print(wrapper(1, 2, c=3))
# forwarding (1, 2) {'c': 3}
# 6
```

## Full parameter order

The order of parameter kinds in a definition must always be:

1. Positional-only (`x`, `y`, then `/`)
2. Positional-or-keyword (`x`, `y`)
3. `*args` (or bare `*`)
4. Keyword-only (`key=value` after `*`)
5. `**kwargs`

## Trade-offs

| What you get | Benefit | Cost |
|---|---|---|
| Positional-only (`/`) | Frees the author to rename the parameter later without breaking callers | Callers cannot self-document a call with `divide(numerator=10, denominator=4)` |
| Keyword-only (`*`) | Callers must name the argument — self-documenting, order-mistake-proof | An extra `*` in the signature to remember; positional-only callers get `TypeError` |
| `*args`/`**kwargs` forwarding | A wrapper works with any signature the wrapped function has | `inspect.signature` on the wrapper alone shows `(*args, **kwargs)`, hiding the real parameters (see [Decorators](/python/en/functions-deep/decorators/) for the `functools.wraps` fix) |
| Unpacking (`*`/`**`) at a call site | Build the argument list/dict dynamically, e.g. from config or another function's return value | A mismatch between the unpacked structure and the signature only fails at call time, not at definition time |
| Mutable default (`items=[]`) / `datetime.now()` default | Looks like "a fresh empty/current value every call" | Evaluated once at definition time — every call that does not override it shares (or freezes) the same object |

## Common Misconceptions

- **"Positional-only parameters are just a style preference — you can always pass them by name"** — fact: `/` makes it a real `TypeError` at the call site to pass those parameters by keyword, not a lint warning.
- **"`**kwargs` behaves like a mutable default — mutating it leaks into the next call"** — fact: `**kwargs` is a brand-new dict built by Python on every call; only an actual *default value* (`items=[]`) is created once and shared. Do not confuse the two.
- **"`def f(when=datetime.now())` gives every call a fresh timestamp"** — fact: `datetime.now()` runs exactly once, when the `def` statement executes, so `when` is the same frozen instant on every call that does not override it — the same class of bug as a mutable default, just with a non-obviously-mutable value.
- **"`*args` and `**kwargs` in a signature and `*args`/`**kwargs` at a call site do the same thing"** — fact: in a signature they *gather* extra arguments into a tuple/dict; at a call site the identical syntax *spreads* a tuple/dict into separate arguments — opposite directions, same symbols.
- **"A `TypeError` about positional-only arguments means the function doesn't accept that argument at all"** — fact: it still accepts the value — only not by that keyword name; passing it positionally in the right slot works fine.

## Reading AI-generated code

- Does a default argument look like `def f(x, when=datetime.now())` or any other function call as a default (not just `[]`/`{}`)? It only runs once, at definition time, exactly like a mutable default.
- Does a wrapper function `def wrapper(*a, **kw)` actually forward *every* argument to the wrapped call (`func(*a, **kw)`), or does it drop or reorder some?
- Is a parameter documented as "must be passed by name" but the signature has no `*` before it? Nothing enforces that contract — a caller can still pass it positionally.
- Does code unpack a dict into keyword arguments (`f(**config)`) where `config`'s keys are not guaranteed to match `f`'s parameter names? A typo'd or extra key raises `TypeError: f() got an unexpected keyword argument`.
- Is `*args`/`**kwargs` used in a signature where the function only ever expects a fixed, known set of parameters? Explicit named parameters (with `/`/`*` where appropriate) document the contract better and let a type checker catch mismatches.

`datetime.now()` in the default value is evaluated **once**, when the `def create_ticket(...)` statement runs — not on every call. Every ticket created without an explicit `opened_at` gets the exact same frozen timestamp, no matter how much real time passes between calls in a long-running process (a web server, a worker process). The printed line is `True`, which is almost certainly not the intent for a field named `opened_at`. This is the same underlying bug class as the mutable-default-argument trap, just with a non-obviously-mutable default. The fix is the same `None`-sentinel pattern: `def create_ticket(title, opened_at=None): opened_at = opened_at if opened_at is not None else datetime.now()`.

<Callout title="The mutable default argument trap">
Never use a mutable object (list, dict, set) — or any function call whose result varies over time, like `datetime.now()` — as a default argument value.
Default values are evaluated **once** at function definition time — not on each call.
All callers share the same object (or the same frozen value):

```python
# WRONG — all calls share the same list
def add_item(item, container=[]):
    container.append(item)
    return container

# RIGHT — use None and create inside
def add_item(item, container=None):
    if container is None:
        container = []
    container.append(item)
    return container
```

The `None` sentinel pattern is the standard Python idiom for both mutable defaults and "evaluate this fresh on every call" defaults like timestamps.
</Callout>
